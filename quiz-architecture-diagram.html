Claude Quiz Generator and Grader — actual architecture

Two entry points now, not one — Quiz.razor (untimed practice) and TimedQuiz.razor (timed exam simulation) — but still three separate calls, not one agent freely choosing among four tools. Both callers share GetQuestionAsync and GradeAsync; only Quiz.razor also calls RecommendNextAsync, since timed mode has no adaptive routing. Only question-generation actually lets Claude pick a tool — grading and recommending-next each offer exactly one tool, forced.

Quiz.razor
Practice mode
Untimed, student-paced study. Requests a question, submits an answer, and can ask what to study next — the only caller that reads session performance and calls RecommendNextAsync.
TimedQuiz.razor
Timed exam mode
Fixed question count on a running clock, simulating the real exam. Requests questions and grades answers through the exact same two calls as practice mode — never calls RecommendNextAsync.

All three "Claude API" boxes are the same endpoint — drawn separately because no single request ever carries more than one call's tools at once.

GetQuestionAsync's avoid-list (recent prompts + recent formats) now comes from whichever caller is asking — Quiz.razor and TimedQuiz.razor each feed back their own session history so Claude steers away from repeating itself, instead of one caller's history silently covering for the other's blind spot.

TimedQuiz.razor can also defer GradeAsync until the student clicks Finish Quiz, for questions marked for review — practice mode always grades immediately.
